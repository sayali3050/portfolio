01Why local?

Plenty of teams want to "chat with their documents" but can't send internal files to a third-party API, whether for privacy, compliance or cost reasons. I wanted an assistant that gives grounded answers with citations while keeping all data on the machine and costing nothing per query.

02How it works

  1. UploadDrop in a PDF or text file through the FastAPI backend.
  2. Chunk & embedLangChain splits the document into passages, and HuggingFace embeddings turn each one into a vector.
  3. IndexVectors are stored in a local FAISS index for fast similarity search.
  4. RetrieveFor each question, the most relevant passages are pulled from FAISS.
  5. Answer with sourcesA local Llama 3.2 model, running on Ollama, writes an answer grounded only in those passages and cites where each fact came from.

03Design decisions

  • Citations are non-negotiable. An answer without a source is hard to trust. Showing the passage lets the user verify it in seconds.
  • No API keys at all. Embeddings and generation both run locally, so setup is just "install and run", with zero external cost.
  • Swappable parts. LangChain keeps the embedding model, vector store and LLM loosely coupled, so any of them can be upgraded independently.
Retrieve, then generate. The model only answers from passages it was handed, which is what keeps it honest about the documents.

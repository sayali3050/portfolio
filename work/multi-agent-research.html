01The idea

One big prompt that asks an LLM to "research this and tell me what to do" tends to blur three very different jobs together: finding information, making sense of it, and committing to a decision. When something goes wrong, it's hard to tell which part failed.

This project splits those jobs across specialized agents, each with a narrow role, so every step is focused, inspectable and easier to improve on its own.

02How it works

  1. Request comes in through the APIA question or decision to support is sent to a FastAPI endpoint.
  2. Retrieval agent gathers evidenceIt uses RAG to pull the most relevant passages from the knowledge sources instead of relying on the model's memory.
  3. Analysis agent reasons over itIt compares and summarizes what the retrieved evidence says.
  4. Decision agent commitsIt turns the analysis into a recommendation, with the supporting evidence attached.
  5. Everything is loggedEach agent's input and output is logged, so a run can be traced and debugged after the fact.

03Design decisions

  • Narrow roles over one mega-prompt. Smaller, single-purpose prompts are easier to test and tune than one prompt that does everything.
  • Grounding first. The decision step only sees what retrieval and analysis produced, which keeps recommendations tied to evidence.
  • REST API with logging. Exposing the system as an API made it usable from other apps, and logging made runs reproducible and stable to operate.
The core design question in a multi-agent system is orchestration: which agent does what, and what each one is allowed to see.
